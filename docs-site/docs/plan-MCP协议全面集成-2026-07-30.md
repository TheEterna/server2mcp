## 〇、给董事长的事实交代（必读，含一条客观技术事实）

**背景重述**（不假设董事长记得）：本项目 api2mcp4j（内部名 server2mcp）是一个 Spring Boot Starter，作用是把现有 Spring `@RestController` 接口**零改动**自动暴露为 MCP 的 Tool / Resource / Prompt / Complete。它自己**不实现 MCP 协议**，而是封装在 **MCP Java SDK + Spring AI** 之上——这一点决定了本次集成的物理边界。

**董事长的判断完全正确，且比预估更严重**：
1. 代码最后一次修改是 **2025-10-22**，距今 9 个月（来源：`git log -1 -- server2mcp-core`）。
2. 项目**当前完全无法构建**——依赖的 `spring-ai 1.1.0-SNAPSHOT` 与 `mcp-sdk 0.14.0-SNAPSHOT` 快照源已失效，本地 `~/.m2` 里 `mcp-0.14.0-SNAPSHOT` 只剩下载失败残留的 `.lastUpdated` 空壳文件（来源：`mvn -o dependency:resolve` 实测 + `ls ~/.m2/.../0.14.0-SNAPSHOT/`）。
3. 项目停留在协议 **2025-06-18** 时代，协议已走到 **2026-07-28**，中间跨了 2 个正式版本。

**一条必须报告的客观技术事实（CEO 批判精神条款）**：

> 董事长要求"全面集成 MCP 协议最新特性"。协议最新版本是 **2026-07-28**（三天前发布，是 MCP 诞生以来最大改版）。但截至今日，**Java 生态没有任何 SDK 支持 2026-07-28**——官方博文明确列出 Tier 1 SDK 为 TypeScript / Python / Go / C#，Rust 为 beta，**Java 未在列**；MCP Java SDK 最新正式版 `2.0.0`（2026-06-11）与 Spring AI 最新正式版 `2.0.0`（2026-06-12）均只实现 **2025-11-25**。
>
> 本项目是 SDK 的上层封装，不能越过 SDK 自己实现协议传输层（那等于重写一个 Java SDK，违背项目定位且不可维护）。
>
> **因此"全面集成"的最大可达 = 2025-11-25 协议全量特性 + 依赖升到生态最新正式版 + 为 2026-07-28 预留架构。** 这不是打折，这是 Java 生态今天的天花板；2026-07-28 部分等 Java SDK 跟进后再启第二战役。

**CEO 决策（不推选项）**：按上述最大可达全量执行，分三期落地，见第三节。

### 2.3 迁移冲击面

**61 个 Java 文件**直接 import `io.modelcontextprotocol.*` 或 `org.springframework.ai.*`（共 108+11+8+10 = 137 个 java 文件）。高频耦合点：

| 耦合类 | 引用数 | 2.0 变更 |

| `io.modelcontextprotocol.util.Assert` | 11 | 待验证是否留名 |
| `McpServerFeatures.*Specification` | 6+ | 待验证 |
| `io.modelcontextprotocol.util.DeafaultMcpUriTemplateManagerFactory` | 4 | SDK 侧类名有 typo（`Deafault`），2.0 可能已修正 |
| `org.springframework.ai.util.json.JsonParser` | 2 | **已移除** → `JsonHelper` / `JacksonUtils.getDefaultJsonMapper()` |
| `org.springframework.ai.tool.annotation.Tool` / `ToolParam` | 3 / 3 | 待验证（本项目 `ToolDesParser`/`ToolParamParser` 依赖它） |
| transport `mcp-spring-webmvc` / `-webflux` | pom | groupId `io.modelcontextprotocol.sdk` → **`org.springframework.ai`**（实测确认） |

**已知连锁反应（牵一发动全身，核心铁律 #2）**：
1. Spring AI 2.0 要求 **Spring Boot 4.0/4.1 + Spring Framework 7.0**（来源：Spring AI 2.0.0 GA 公告）→ 本项目 Spring Boot 3.4.4 必须跨 2 个大版本升级。
2. Spring AI 2.0 要求 **Jackson 3**（`com.fasterxml.jackson` → `tools.jackson`）→ 本项目 `JacksonUtils`、`JacksonDesParser`、`JacksonParamParser`、`ConvertUtil` 全部基于 Jackson 2，须逐一迁移。
3. victools jsonschema 4.37.0 是否兼容 Jackson 3 / Spring Framework 7 待验证 → 可能须升 5.0.0，`GenSchemaUtils` 受影响。
4. **战略级发现**：Spring AI 2.0 core 已自带 `org.springframework.ai.mcp.annotation.McpTool`，与本项目 `com.ai.plug.core.annotation.McpTool` **同名不同包**。本项目差异化价值（Controller 零改动自动暴露）依然独有且更强，但自定义 MCP 实体的注解已被官方覆盖——需在文档中明确划清定位，避免用户 import 错。**本期不删不改本项目任何公开注解**（删公开 API 属红线）。

### Phase 0 实际改动清单（2026-07-30）

**pom（3 处）**
- 根 `pom.xml`：Spring Boot `3.4.4→4.1.0`、Spring AI `1.1.0-SNAPSHOT→2.0.0`、MCP SDK `0.14.0-SNAPSHOT→2.0.0`、victools `4.37.0→5.0.0`；删除失效的 `mcp-annotations 0.2.0-PRIVATE` 属性与注释残骸；删除三个已失效的 milestone/snapshot 仓库声明（依赖已全在 Maven Central）。`java.version` 保持 **17**（实证依赖字节码 major version=61）。
- `server2mcp-test/pom.xml`：parent 升 `4.1.0`；移除 geotools 三依赖 + osgeo 仓库（零引用死依赖，且其 `releases: disabled` 使 release 版本就无法解析——既有构建阻塞点，非本次引入）。

**Java（13 个文件）**
- Jackson 2 → 3 包名迁移：`com.fasterxml.jackson.{databind,core}` → `tools.jackson.{databind,core}`；`JsonProcessingException` → `JacksonException`（后者继承 `RuntimeException`，已 unchecked）。**注解包 `com.fasterxml.jackson.annotation.*` 保持不变**（Jackson 3 复用 jackson-annotations 2.x）。
- `JacksonUtils`：原为 Spring AI 复制品，反射加载的 `Jdk8Module`/`JavaTimeModule`/`ParameterNamesModule` 在 Jackson 3 下已并入核心、会全部落空并静默返回空列表（时间类型序列化退化的隐性 bug）→ 收口为委托 `org.springframework.ai.util.JacksonUtils`。
- `JsonNode` 遍历 API：`fields()` → `properties()`、`elements()` → `values()`（3 处）。
- `ToolDefinitionBuilder.buildToolInputSchema`：返回类型 `McpSchema.JsonSchema` → `Map<String,Object>`（SDK 2.0 统一）；`ModelOptionsUtils.jsonToObject` 已被 Spring AI 2.0 移除 → 改用本项目 `JsonParser`。
- `McpToolProvider`：`Sync/AsyncToolSpecification` 构造器由 3 参数收敛为 `(tool, callHandler)` 2 参数。
- `DefaultMcpCallToolResultConverter`：`CallToolResult` 2 参数便利构造器已移除 → 9 处改为 `builder().addTextContent(…)/.content(…).isError(…).build()`。
- `McpElicitation`：`ElicitRequest` 已成接口 → 变量类型改 `ElicitFormRequest.Builder`。
- SDK 自身 typo 修正：`DeafaultMcpUriTemplateManagerFactory` → `DefaultMcpUriTemplateManagerFactory`（4 文件）；`io.modelcontextprotocol.json.jackson` → `.json.jackson3`。

**公开 API 影响**：本项目框架注解、`IXxxContext`、`AbstractXxxParser` SPI、`McpCallToolResultConverter` 全部留名留签名。唯二不可避免的签名变化为 Jackson 3 强制连带：`JacksonUtils.instantiateAvailableModules()` 元素类型 `Module`→`JacksonModule`，`JsonParser.toJson/toTypedObject` 的 `throws` 由 `JsonProcessingException`→`JacksonException`。

**未做（明确留痕，非遗漏）**：存量文件的 `@header-start` 文件头回填仍按既定独立 Sprint 处理——本次为纯依赖迁移，批量插入文件头会淹没 diff、妨碍审计者辨识真实语义改动。
