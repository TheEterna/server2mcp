> 来源：async subagent `a31b4852b37703dad` · 子任务"部署脚本深度审查"
> 结论：与首轮报告一致，**scripts/deploy-cf-pages.sh 本身基本安全**（CF_API_TOKEN 通过 bash 数组传递，无 echo/log 泄漏，无命令注入）。**新发现 2 项非隐私问题**：

### 🟡 中等：`wrangler pages deploy` 失败被吞掉

- **文件**：`scripts/deploy-cf-pages.sh`
- **行号**：113
- **问题**：`DEPLOY_OUT=$(wrangler pages deploy .vitepress/dist --project-name ... --branch main --commit-dirty=true 2>&1) && echo "$DEPLOY_OUT" | tail -5`
  - `&&` 链下若 wrangler 失败，`echo` 不执行，但 `set -eu` 也不退出
  - **后果**：步骤 5 失败后，步骤 6（Custom Domain）+ 步骤 7（DNS CNAME）+ 步骤 8（Git 集成）+ 步骤 9（Print URLs）继续执行并"假装成功"
  - 终端输出"Deployment complete"是误导
- **建议**：将 `&& echo` 改为 `|| { echo "❌ wrangler deploy failed"; exit 1; }`，让 `set -eu` 真正触发退出

### 🟢 低：`production_branch` 与 `--branch main` 不一致

- **文件**：`scripts/deploy-cf-pages.sh`（line 78 附近）+ `wrangler.toml`（行 18）
- **冲突点**：
  - `wrangler.toml` `[build]` 不指定 production_branch → 默认 `main`（CF Pages dashboard 设置）
  - 脚本创建 Pages project 时显式 `production_branch: "docs-site"`
  - 后续 `wrangler --branch main` 上传的部署会被 CF 当作**预览分支**，不挂到自定义域名
- **后果**：docs.xiaohan.chat 仍指向首次 Direct Upload 时的旧版本，新 push master 看不到更新
- **建议**：统一为 `main`（与 git 主分支一致）
